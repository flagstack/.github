# FlagStack Governance

FlagStack is currently a maintainer-led project in its early stages.

## Maintainers

Maintainers are responsible for the technical direction and stewardship of the project. This includes:

- reviewing and integrating contributions;
- deciding release scope and timing;
- maintaining project quality and security standards;
- resolving architectural disagreements;
- enforcing the Code of Conduct;
- maintaining compatibility across the core product and official SDKs.

## Decision making

Routine changes are decided through normal issue and pull request review.

Substantial changes should be discussed before implementation, particularly when they affect:

- public APIs or SDK contracts;
- persistence or migration strategy;
- authentication, authorisation, or security boundaries;
- compatibility between self-hosted FlagStack and FlagStack Cloud;
- cross-repository architecture;
- licensing or contribution policy.

Maintainers make the final decision when consensus cannot be reached. Decisions should favour the long-term maintainability, usability, security, and sustainability of FlagStack.

## Becoming a maintainer

There is no automatic path based purely on contribution count. As the community grows, contributors who consistently demonstrate sound judgement, constructive participation, and sustained responsibility may be invited to take on maintainer responsibilities.

## Evolution

This governance model is intentionally lightweight for the project's current stage. It may be expanded as the number of maintainers, contributors, users, and releases grows.
